# Disaster Tweet Classification — NLP Project

An end-to-end NLP pipeline that classifies tweets as **real disaster (1)** or **not a
disaster (0)**, built to satisfy every part of the project brief (`NLP Project for Disaster
Tweet Classification.pdf`): data exploration, preparation, feature engineering, model
selection, evaluation/validation, and deployment behind a web interface.

## Results at a glance

| Metric | Score |
|---|---|
| Test Accuracy | **79.9%** |
| Test Precision | **78.6%** |
| Test Recall | **73.1%** |
| Test F1-score | **75.8%** |

Final model: **Logistic Regression** over TF-IDF (uni-grams, 8,000 features) + engineered
tweet features (hashtags, mentions, URLs, punctuation intensity), tuned with `GridSearchCV`.
Four model families (Logistic Regression, Multinomial Naive Bayes, Random Forest, Linear
SVM) were benchmarked with 5-fold cross-validation before selecting and tuning the winner —
see `reports/final_model_comparison.csv` for the full comparison table.

## How each part of the brief was addressed

**Part 1 — Data Exploration & Preparation**
- Loaded and inspected the 7,613-row dataset with pandas (dtypes, missing values, duplicates).
- Visualized class balance (57% / 43%), tweet length distributions, top keywords per class,
  and word clouds.
- Cleaned text (lowercasing, URL/mention/HTML removal, punctuation & digit stripping),
  tokenized, removed stopwords, and lemmatized with NLTK.
- Converted labels to numeric (already 0/1 in the source data — verified).
- Split into stratified train/test sets (80/20).

**Part 2 — Feature Engineering & Model Selection**
- TF-IDF (uni-/bi-grams) as the primary text representation, combined via `ColumnTransformer`
  with hand-crafted numeric features (hashtag/mention/URL presence, punctuation counts, word
  count).
- Benchmarked Logistic Regression, Multinomial Naive Bayes, Random Forest, and Linear SVM
  (SGD) with 5-fold stratified cross-validation (F1-score).
- Tuned the best-performing family with `GridSearchCV` over vectorizer and classifier
  hyperparameters.

**Part 3 — Model Evaluation & Validation**
- Evaluated the tuned pipeline on a held-out test set: accuracy, precision, recall, F1,
  confusion matrix, ROC curve (AUC), and precision-recall curve.
- Checked for overfitting/underfitting by comparing train vs. test F1.
- Compared all four model families on the same test set in one final table/chart.
- Manual error analysis on misclassified tweets to characterize remaining weaknesses
  (mostly sarcasm/metaphor — the exact challenge called out in the brief).

**Part 4 — Deployment with Web Interface**
- The tuned pipeline is serialized as a single `joblib` artifact so preprocessing and
  inference are always in sync.
- A Flask app (`app/app.py`) loads that artifact and exposes:
  - `GET /` — a web form where a user pastes a tweet and gets an instant prediction with a
    confidence score.
  - `POST /api/predict` — a JSON API (`{"text": "..."}` → `{"label": ..., "confidence": ...}`)
    for programmatic/integration use.
  - `GET /health` — a simple health check for deployment platforms.

## How to run it

### 1. Set up the environment
```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. (Re-)run the analysis notebook
```bash
cd notebooks
jupyter notebook Disaster_Tweet_Classification.ipynb
# or, to re-run headlessly and regenerate all charts + the model file:
jupyter nbconvert --to notebook --execute --inplace Disaster_Tweet_Classification.ipynb
```
This regenerates everything in `reports/` and `models/`.

### 3. Run the web app
```bash
cd app
python app.py
```
Open **http://127.0.0.1:5000** in your browser.

### 4. Deploy (Heroku / Render / any cloud VM)
The app is a standard Flask app — add a `Procfile` with:
```
web: gunicorn app:app
```
(install `gunicorn` and add it to `requirements.txt`), then push to your platform of choice.
No code changes are needed; the model artifact loads from a relative path.

## Possible future improvements
- Fine-tune a transformer (BERT/DistilBERT) for better handling of sarcasm and metaphor.
- Use the `location` column (with geocoding/cleanup) as an additional feature.
- Connect to the live Twitter/X API for real-time streaming classification.
- Add model monitoring and periodic retraining as language and slang evolve.
